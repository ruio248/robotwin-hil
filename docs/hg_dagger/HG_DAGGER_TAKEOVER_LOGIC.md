# HG-DAgger：专家接管逻辑

`handover_to_tray` 的脚本专家分六阶段：左臂抓杆、抬起、送至交接位、右臂抓取、左臂放开并后撤、右臂放入托盘。任务定义在 `robotwin_hil/overlay/envs/handover_to_tray.py`；`infer_recovery_state()` 根据当前物体/夹爪状态推断可恢复分支，`recover_from_current_state()` / `recovery_stage_iterator()` 执行相应专家后缀。**不是**仅按 rollout 时间或固定帧数猜阶段。状态不安全、规划失败、关节不合法或最终任务未成功时必须记失败，不能为了提高救回率静默放宽安全门。

| 实际状态（按优先级判断） | 恢复分支 | 专家处理 |
| --- | --- | --- |
| 杆已在托盘位置但夹爪未完全松开 | `release_at_tray` | 打开两侧夹爪，再检查最终成功。 |
| 右臂持杆 | `receiver_place` | 若左臂也持杆，先松开/后撤左臂；随后右臂对准托盘放置。 |
| 仅左臂持杆 | `resume_handover` | 回到交接位、确保右夹爪能接近并抓牢，再松开左臂、完成放置。 |
| 两臂均未持杆、杆悬在托盘附近 | `guided_place_from_air` | 右臂在当前位置重新抓杆并完成放置。 |
| 两臂均未持杆且不满足上项 | `restart_source_grasp` | 从左臂重新抓杆，重走必要后缀；超出可恢复工作空间则拒绝。 |

上述分支依赖仿真器的物体位姿/接触等特权状态；迁移到真实机器人时必须另做可观测性与安全验证，不能直接把仿真判断当真实传感器读数。

全程模式下策略自主运行；操作者观察到偏离时按 `i`，当前未执行完的策略 chunk 作废，脚本接管。按 `r` 可在该模式中交还策略；`x` 放弃本条，`q` 退出会话。接管时记录请求点、物理状态、推断阶段、执行的专家阶段、规划与任务结果。人工请求是事件标签，D 的低分不是未经验证的自动接管指令。

单阶段对照模式则由脚本专家先完成阶段 1–5；只有 `handoff_record` 判定阶段 6 交接状态合格后才运行策略。前缀失败单列，不进末段分母。阶段 6 按 `i` 后专家负责直到终局，不使用 `r`；`x` 放弃、`q` 退出。详见 [末段配对协议](ONE_STAGE_DAGGER_PROTOCOL_20261013.md) 与 `robotwin_hil/overlay/scripts/one_stage_dagger.py`。

跨任务扩展应先定义：可观测阶段判定、每阶段常见错误、安全介入窗口、专家恢复函数与拒绝条件；然后冻结失败场景，在策略真实失败前多个预定窗口做可复现诊断，分别报告专家规划成功、物理安全、原任务成功与接管后稳定性。仅重跑相同 seed 不保证重现旧轨迹；精确分支实验须保存动作前缀或仿真状态。回放诊断标 `diagnostic_only=true`、`accepted_for_training=false`，不能冒充真人 HIL 数据或声称所有失败都可救回。
